Discord blocked screen sharing for Brazilian accounts.

It took me 3 lines of JavaScript to turn the block off.

No exploit. No protocol reverse engineering. I did not intercept a single request.

I opened the console and dispatched an action that Discord's own client already exposes:

APEX_EXPERIMENT_SESSION_OVERRIDE_CREATE -> variantId: 0

That's it. Screen share unlocked.

What that actually means:

The definition of the "2026-08-video-guard" experiment is shipped into your browser. The client downloads the rule, reads the rule, and decides on its own whether to block you. The override mechanism is part of the same bundle.

In other words: the restriction was never a control. It was an if statement.

And here is the part that should bother more people - this is not an isolated case, it's a pattern:

-> A client-side feature flag is not authorization.
-> A hidden button is not a denied permission.
-> If the decision dies in the frontend, it does not exist.

A real control would be enforced on the media server: the stream gets rejected the moment it is published. The button doesn't disappear - the packet doesn't go through.

Hiding the UI protects you from users who never opened DevTools. That is a shrinking audience.
